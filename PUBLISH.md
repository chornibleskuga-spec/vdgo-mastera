# Как выложить эту версию на GitHub

В архиве — версия «ВДГО Мастер» с оформлением в стиле macOS и адаптацией под
компьютер и телефон. Код самого приложения не изменён: файлы
`assets/index-*.js` и `assets/index-*.css` побайтово совпадают с теми, что
лежат в репозитории. Добавлены только внешние файлы темы.

## Что внутри

| Файл | Назначение |
| --- | --- |
| `index.html` | страница приложения (добавлены подключение темы и `viewport-fit=cover`) |
| `assets/` | сам собранный интерфейс: изменена **только навигация** (см. ниже), остальное побайтово как в репозитории |
| `macos-theme.css` | оформление: палитра macOS, шрифт SF Pro / Inter, боковая панель, ящик на телефоне |
| `macos-icons.css` | иконки в стиле macOS: маски на все иконки приложения (файл сгенерирован) |
| `macos-chrome.js` | полоса окна, иконки панели, кнопка разделов для телефона, цвет полосы состояния |
| `macos-dialogs.js` | свои окна подтверждения вместо системных `confirm`/`alert` (см. ниже) |
| `macos-actions.js` | удаление «Истории обзвона» за день (см. «Что добавлено») |
| `manifest.json` | манифест PWA: пути сделаны относительными, чтобы установка работала и в подпапке |
| `sw.js`, `peerjs.min.js`, `tabel-template.json` | как было |
| иконки | новые, в стиле Apple: `icon.svg`, `icon-512/192.png`, `apple-touch-icon.png` (180), `favicon.png/ico`, maskable-версии, `icon-macos-*.png` для Dock |
| `.nojekyll` | чтобы GitHub Pages не обрабатывал файлы через Jekyll |

## Иконка

Иконка перерисована в стиле macOS и Apple: форма — «сквиркл» (суперэллипс), как у
системных иконок; вертикальный градиент системного синего с подсветкой сверху,
мягкая тень, направленная вниз, и стеклянный экран планшета в белом корпусе.

| Файл | Для чего |
| --- | --- |
| `icon.svg` | векторная версия для вкладки браузера и современных систем |
| `icon-512.png`, `icon-192.png` | установка приложения (Android, Chrome, Edge) |
| `apple-touch-icon.png` | домашний экран iPhone и iPad, 180×180 |
| `favicon.png`, `favicon.ico` | вкладка браузера, включая 16 и 32 px |
| `icon-maskable-192/512.png` | те же размеры, но глиф меньше — не обрезается маской лаунчера |
| `icon-macos-512/256/128.png` | «доковый» вид: сквиркл с полями и тенью, для ярлыков и презентаций |

Иконки перерисованы скриптом `tools/make-icon.py` — при желании можно поменять
цвета или пропорции и собрать заново.

## Что изменено в собранном коде

Ровно одно: навигация, кассы и мелкие правки данных. Это пятнадцать замен
в файле `assets/index-*.js`:

1. `{id:"apps",label:"Приложения"},` — удалено из массива разделов;
2. в конец массива добавлены `{id:"calculator",label:"Калькулятор"}` и
   `{id:"reminders",label:"Напоминания"}`;
3. `case"calculator"` теперь передаёт начальный раздел, поэтому калькулятор
   открывается сразу, а не через меню плиток;
4. то же для `case"reminders"`;
5. компонент меню плиток принимает этот начальный раздел;
6–7. каждой ветке передан свой `key`;
8. в шапку дня «Истории обзвона» добавлена кнопка «Удалить день»;
9. в справочнике «1С коды» у пункта «Журнал регистрации заявок» код `512`
   заменён на `215`;
10. пункт панели `ФАР` → `ФИАР`;
11. заголовок раздела `ФАР — Формирование Актов Работ` →
    `ФИАР — Формирование и Анализ Реестра`;
12. обновление кассы научено добавлению и удалению: если id не найден — запись
    добавляется, флаг `__delete` — убирает её из списка;
13. в шапку раздела «Кассы» добавлена кнопка «Добавить»;
14. в карточку кассы добавлена кнопка «Удалить кассу»;
15. в окне «Передать адрес» кружки слесарей окрашены по-разному (цвет берётся
    из палитры приложения), кружок крупнее, фамилия крупнее и полужирная.

Про `key` — важная деталь. Оба инструмента рисует один и тот же компонент меню,
и он хранит выбранный инструмент во внутреннем состоянии. React при переключении
между двумя ветками одного типа компонент не пересоздаёт, а только меняет
свойства, поэтому без разных `key` переход «Калькулятор → Напоминания» оставлял
на экране калькулятор. Разные `key` заставляют React пересоздать экран.

Всё остальное — вёрстка, данные, синхронизация, Excel, KPI — не тронуто; это
проверяется побайтовым сравнением с файлами репозитория. Ветка `case"apps"`
осталась в коде как недостижимая: если понадобится вернуть раздел «Приложения»,
достаточно вернуть пункт в массив.

## Что добавлено: удаление «Истории обзвона» за день

Раньше историю обзвона можно было чистить только по одной записи — за каждого
диспетчера отдельно. Теперь в шапке каждого дня есть кнопка **«Удалить день»**:
она удаляет все записи за этот день сразу, спросив подтверждение и назвав их
количество.

Работа с данными — в `macos-actions.js`, кнопка лишь вызывает её. Что делает
удаление:

* убирает записи этого дня из `vdgo_dispatcher` (ключ, в котором приложение
  хранит историю обзвона);
* пишет метки удаления — в `vdgo_dispatcher_deleted` (как это делает само
  приложение при удалении одной записи) и в общий список `vdgo_deleted_ids`,
  по которому слияние при синхронизации отбрасывает удалённое. Без меток записи
  вернулись бы с другого устройства;
* отправляет событие `vdgo_data_changed`: список на экране перечитывается, и
  запускается отправка данных в Firebase.

Метки удаления живут час — ровно как в самом приложении для кейсов.

## Что добавлено: кассы

Приложение умело только менять статус кассы и закреплять за ней слесаря —
обновление существующей записи по id. Теперь в разделе «Кассы» есть:

* **«Добавить»** в шапке раздела — открывается окно с полями: № кассы
  (обязательно), наименование (по умолчанию `Касса ККТ "aQsi-5Ф"`),
  инвентарный №, статус (в работе / в ремонте / списана) и слесарь, за которым
  касса закрепляется. Номер проверяется на повтор: касса с таким же номером не
  добавится, окно останется открытым и покажет причину;
* **«Изменить»** в карточке кассы — то же окно, но заполненное текущими
  значениями: исправляются номер, наименование, инвентарный, статус и
  закреплённый слесарь;
* **«Удалить»** в карточке — с подтверждением и напоминанием, если касса за
  кем-то закреплена.

Добавление, изменение и удаление идут **тем же путём, что и обычное
изменение** — через обновляющую функцию приложения, поэтому сразу обновляются
состояние, запись в localStorage и отправка данных на другие устройства. Для
этого тело функции дополнено: если id не найден — запись добавляется, флаг
`__delete` убирает её из списка. При удалении дополнительно пишутся метки
удаления, иначе касса вернулась бы с другого устройства при синхронизации.

Закрепление слесаря за кассой было и раньше: откройте кассу и в разделе
«Закреплен за слесарем» выберите фамилию из списка. Теперь тот же выбор есть и в
окне добавления кассы.

## KPI планшет: месяцы, обозначения ПК и ОДК, цвета

**Данные разделены по месяцам.** Ячейка планшета хранилась под ключом
«слесарь_день», где день — просто число 1..31; месяца в ключе не было, поэтому
сентябрь и октябрь показывали одни и те же числа. Теперь ключ выглядит как
«слесарь_2026-9-5», и каждый месяц живёт отдельно: заполнили сентябрь,
переключились на октябрь — он пустой, а сентябрь возвращается, как только
переключитесь обратно. Выгрузка в Excel тоже берёт числа только своего месяца.

Старые записи (сделанные до обновления) переносятся на новый вид
автоматически при первом открытии: они относятся к текущему месяцу — именно за
него их и заполняли. Перенос делает `macos-actions.js`, подключённый **раньше**
кода приложения, поэтому он проходит до чтения данных.

**Два новых обозначения: ПК и ОДК.** Работают так же, как В, ДО, ОТ и Б:
вводите в ячейку — значение распознаётся, получает свой цвет и попадает в
условные обозначения выгрузки.

**Цвета яркие и больше не совпадают.** Раньше суббота была фиолетовой (как
«Б»), воскресенье — оранжевым (как «ДО»), а заливки были бледными. Теперь
девять разных ярких цветов, и ни одна пара не повторяется:

| Что | Цвет | | Что | Цвет |
| --- | --- | --- | --- | --- |
| Число (работы) | зелёный `#34C759` | | ПК | бирюзовый `#00A79A` |
| В — выходной | красный `#FF3B30` | | ОДК | жёлтый `#9A7B00` |
| ДО — доп. выходной | оранжевый `#FF9500` | | Суббота | индиго `#5E5CE6` |
| ОТ — отгул | синий `#0A84FF` | | Воскресенье | малиновый `#FF375F` |
| Б — больничный | фиолетовый `#BF5AF2` | | | |

Заливки ячеек стали насыщеннее (0.34 вместо 0.22), поэтому цвет видно сразу.

**Дежурства тоже привязаны к месяцу.** Раньше в записи дежурства месяца не
было — только слесарь и тип дня. Из-за этого дежурство, поставленное в одном
месяце, показывалось во всех, а снятие убирало его сразу везде; кнопка
«Очистить все дежурства за <месяц>» очищала список целиком, хотя в
подтверждении назван один месяц. Теперь запись хранит месяц и год, поиск,
снятие, показ в планшете, выгрузка и очистка работают по месяцу. Старые
дежурства (без месяца) переносятся на текущий месяц автоматически.

Значения ПК и ОДК в условных обозначениях выгрузки пока оставлены как есть —
скажите, что они означают, и я подпишу их словами.

## Что улучшено: окно «Передать адрес»

Было: у всех слесарей одинаковый синий кружок с инициалами и фамилия мелким
шрифтом — список приходилось читать целиком.

Стало: кружок каждого слесаря окрашен своим цветом (та же палитра, что в кассах:
цвет привязан к id слесаря и не меняется), кружок крупнее — 36 вместо 32 px,
фамилия — 15 px полужирным вместо 14 px обычным. Выбирать можно «по цвету»,
не вчитываясь.

## Что удалено: раздел «ФИАР — Формирование и Анализ Реестра»

Раздел убран из приложения: нет пункта в панели разделов и нет подключения
экрана — в коде не осталось ни одной ссылки на него. Вместе с ним недоступны и
все его возможности: загрузка реестра из Excel, определение района по адресу и
через Nominatim, правила «БИНГО» и выгрузка реестров по группам.

Сам код экрана и его вспомогательные функции (разбор адреса, запросы к
Nominatim, таблица индексов, разбор Excel) остались в файле как **неиспользуемые**
— вырезать их тело надёжно можно только настоящим разборщиком JavaScript, а
попытка вырезать «по скобкам» ломала вторую сборку, поэтому от неё отказались.
На работу приложения это не влияет: без подключения экрана этот код не
выполняется никогда.

## Способ 1. Через сайт GitHub (ничего устанавливать не нужно)

1. Распакуйте архив.
2. Откройте репозиторий: <https://github.com/chornibleskuga-spec/vdgo-mastera>
3. **Add file → Upload files**.
4. Перетащите **всё содержимое распакованной папки** (не саму папку): `index.html`,
   `macos-theme.css`, `macos-icons.css`, `macos-chrome.js`, `manifest.json`, `sw.js`, `assets/`, иконки.
5. Внизу — **Commit changes**.

Результат: файлы заменят одноимённые в репозитории, и через 1–2 минуты (GitHub Pages
кэширует) сайт обновится на прежнем адресе:
<https://chornibleskuga-spec.github.io/vdgo-mastera/>

## Способ 2. Сначала проверить, не трогая рабочую версию (рекомендую)

Загрузите файлы не в корень, а в **папку** `macos/` — тогда новая версия будет
жить рядом со старой:

1. В репозитории: **Add file → Create new file**, имя — `macos/index.html`,
   вставьте содержимое. Так по одному файлу долго.
   Проще: **Add file → Upload files**, и в поле имени пути допишите `macos/`
   перед перетаскиванием — GitHub положит файлы в эту папку.
2. Открывайте: <https://chornibleskuga-spec.github.io/vdgo-mastera/macos/>

Пути в манифесте и service worker относительные, поэтому в подпапке всё работает.
Когда всё устроит — перенесите файлы в корень и удалите папку.

## Способ 3. Через GitHub Desktop (удобнее всего для правок в будущем)

1. Установите <https://desktop.github.com> и войдите в свой аккаунт.
2. **File → Clone repository → chornibleskuga-spec/vdgo-mastera**.
3. Скопируйте содержимое распакованного архива в папку репозитория (с заменой).
4. GitHub Desktop покажет изменения → **Commit to main** → **Push origin**.

## Установка как приложение

* **Компьютер (Chrome/Edge):** открыть адрес → значок установки в адресной строке
  (или меню → «Установить приложение»).
* **Android:** меню браузера → «Установить приложение» / «Добавить на главный экран».
* **iPhone (Safari):** «Поделиться» → «На экран “Домой”».

После установки приложение открывается без адресной строки, а полоса состояния
окрашивается в цвет окна.

## Почему свои окна подтверждения

Приложение подтверждает действия системным `confirm()` — всего 11 вызовов, например
«Сохранить кейс?», «Закрыть кейс?», «Удалить?», «Очистить все дежурства». Беда в
том, что браузер может эти окна не показать:

* в приложении, добавленном на **домашний экран iOS**, системные диалоги в режиме
  standalone не отображаются;
* в Chrome есть галочка «не показывать больше диалоги» — после неё `confirm()`
  молча возвращает `false` до перезагрузки страницы.

В обоих случаях обработчик не выполняется, и кнопка выглядит рабочей, но ничего не
делает. Именно это происходило с «Сохранить» и «Закрыть» в разделе кейсов.

`macos-dialogs.js` подменяет `confirm()` и `alert()` своими окнами, которые
рисуются средствами страницы, — их ничто не блокирует. `confirm()` синхронный, а
окно показывается асинхронно, поэтому применён приём с повторным нажатием: первое
нажатие запоминается и возвращает `false`, а после подтверждения тем же элементом
программно «щёлкают» ещё раз — и обработчик приложения выполняется ровно один раз.

## На что обратить внимание

* **Панель разделов можно свернуть.** Кнопка внизу панели, под пунктом
  «Настройки», сворачивает её до одних иконок; подписи показываются подсказкой
  при наведении, а группы «История» и «Справочники» раскрываются всплывающим
  списком справа. Состояние запоминается на устройстве. На телефоне вместо этого
  — выдвижная панель по кнопке разделов.
* **Пункт «Настройки»** — обычный раздел панели, стоит сразу под
  «Справочниками», той же краской; при открытии подсвечивается синим, как
  остальные разделы. Рисуется своей шестерёнкой: значок приложения в 14 px
  выглядел как солнышко.
* **Полоса окна есть только на телефоне** — там в ней кнопка разделов. На
  компьютере и планшете сверху ничего нет: приложение занимает всё окно.
* **Установка на телефон.** Сайт, добавленный на рабочий стол, открывается без
  адресной строки. В этом режиме сверху остаётся полоса с кнопкой
  разделов — панель навигации выезжает по нажатию. На компьютере в установленном
  приложении полосы нет: она там не нужна, окно уже есть.
* **Синхронизация.** В этой сборке используется рабочая комната
  `vdgo_rooms/default` — та же, что и в текущей версии на GitHub Pages. То есть
  устройства продолжат видеть общие данные. Если нужно сначала посмотреть без
  записи в рабочую базу, скажите — соберу вариант с отдельной комнатой.
* **Права доступа Firebase.** Правила базы сейчас разрешают чтение без входа в
  систему, а адрес базы есть в открытом коде. Это стоит закрыть.
* **Пароли.** Три учётные записи с паролем `111qqqAAA` зашиты в приложение.
* `.nojekyll` нужен, чтобы Pages отдавал файлы как есть. Если загружаете в
  подпапку — положите его рядом с `index.html`.
